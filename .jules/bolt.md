## 2024-05-23 - [Optimization] Buffer vs String Response
**Learning:** Pre-allocating a static string response as a `Buffer` in a raw Node.js HTTP server avoids repeated UTF-8 encoding overhead. While `res.end(string)` performs encoding on every request, `res.end(buffer)` writes directly to the stream. This resulted in a ~3-5% increase in requests per second (~24.6k -> ~25.4k) and reduced latency (~0.6ms) for a simple "Hello World" benchmark. However, combining this with `res.writeHead` (instead of individual `setHeader` calls) yielded a much larger improvement (~20%), highlighting that header management overhead can dominate in micro-benchmarks.
**Action:** For high-throughput raw Node.js servers serving static content, prefer pre-allocated Buffers and consider `writeHead` for batch header sending if maximum performance is critical.
